1 · Change request — mission briefing

Harborline Commerce is migrating its customer portal to segmented infrastructure. A design review identified exposure risks and incomplete traffic controls. Deploy the available security equipment and decide which traffic paths should remain accessible.

Select a component, then select Install at a numbered network position. You may move or remove equipment. Complete the traffic policy matrix. Feedback is withheld until final submission.

Operational requirements

BR-01 Customers connect to the public portal using TLS. Traffic must be distributed across WEB-01 and WEB-02.
BR-02 Internet-originated traffic must be governed at the external boundary; malicious patterns must be prevented before reaching internal workloads.
BR-03 Inspect application-layer requests for common HTTP attacks before processing customer sessions.
BR-04 Web nodes communicate with APP-01/02 only on TCP 8443; direct public access to application instances is prohibited.
BR-05 APP-01/02 access DB-01 on TCP 5432. Neither public clients nor web nodes may connect directly to DB-01.
BR-06 An independent data-tier policy enforcement point must constrain database access, even if an application host is compromised.
BR-07 Privileged SSH sessions must enter from the management subnet through a controlled jump point.
BR-08 A distinct internal boundary must limit DMZ-to-application traffic.

Deployment notes

The numbered positions represent different logical control functions. A single appliance may implement multiple functions in production, but this exercise evaluates separation of security responsibilities.

Equipment may be reused only once. Unused equipment is permitted. The pre-deployment check reports completion counts only; it does not reveal whether a placement or traffic decision is correct.
